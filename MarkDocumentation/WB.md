## 1. Executive Summary & Role Mission

As **WB**, you own the **Web Platform, Interactive Demonstration Dashboard, and Streaming Visualization** of BetterStreamer.

While DC implements the Rust simulation engine, and ML1/ML2 develop content analysis and predictive models, your mission is to make the system **visually tangible, interactive, and demonstrable**. You build the end-to-end web platform that enables researchers, evaluators, and stakeholders to run simulations on demand, watch side-by-side synchronized video playback comparing Baseline ABR against Content-Aware ABR, and inspect real-time telemetry graphs (buffer levels, bandwidth traces, VMAF quality, and rebuffering stalls).

### 2.1 Backend Architecture & Simulation API
- **API Server**:
  - Implement a high-performance backend using **FastAPI (Python)** or **Node.js (Express / Fastify)**.
  - Interface directly with DC's compiled Rust binary (`betterstreamer.exe`) or invoke precomputed simulation traces.
- **REST Endpoints**:
  - `GET /api/catalog/videos`: Returns available video categories (talking head, sports, action, lecture, mixed) with metadata.
  - `GET /api/catalog/traces`: Returns available network profiles (`stable-high`, `moderate`, `sudden-degradation`, `highly-variable`).
  - `POST /api/simulate`: Triggers a simulation run with custom parameters:
    ```json
    {
      "policy": "perceptual",
      "video": "sports_dynamic_01",
      "trace": "sudden-degradation.csv",
      "weight_motion": 0.6,
      "weight_complexity": 0.4,
      "buffer_capacity_s": 12.0
    }
    ```
  - `GET /api/reports/:id`: Fetches the detailed comparison report and timeseries data.
- **Real-Time Streaming / WebSockets**:
  - Provide a WebSocket endpoint (`/ws/telemetry/:session_id`) streaming chunk-by-chunk playback telemetry in real time to power dynamic dashboard gauges.
- **Media Asset Serving**:
  - Static file delivery server for transcoded `.mp4` / `.m4s` video segments and HLS `.m3u8` playlists generated by ML1.

### 2.2 Frontend UI: Synchronized Dual Video Player
- **Side-by-Side Dual Playback**:
  - **Left Player**: Baseline ABR (conventional throughput/buffer).
  - **Right Player**: BetterStreamer Content-Aware ABR.
  - Lock playback clocks so both streams play in exact lockstep.
- **Stall & Rebuffer Visualization**:
  - When the baseline policy experiences a rebuffering event, visually freeze the player with a spinner, show buffer depletion, and display the stall penalty duration ($s$).
- **Live Overlay HUD (Heads-Up Display)**:
  - Overlay floating badges on each player indicating:
    - Active Resolution & Bitrate (e.g., `1080p @ 6000 kbps` vs `480p @ 800 kbps`).
    - Instantaneous VMAF Score (0–100) and SSIM.
    - Chunk Perceptual Priority (`Low`, `Medium`, `High`).

### 2.3 Real-Time Telemetry & Interactive Visualizations
Build synchronized, interactive charts using **Recharts**, **Chart.js**, or **Plotly**:
1. **Network Throughput vs Bitrate Selected**:
   - Plots the replayed bandwidth curve (Mbps) alongside the discrete chunk bitrate selected by each policy.
2. **Buffer Occupancy Curve**:
   - Live graph of player buffer fill level ($0 \dots 20\text{ s}$) with a highlighted rebuffering hazard threshold.
3. **Perceptual Quality (VMAF) Over Time**:
   - Visualizes chunk-by-chunk VMAF score, vividly demonstrating how Content-Aware ABR boosts quality during complex scenes while Baseline ABR lags.
4. **Bandwidth Efficiency / Cumulative MB**:
   - Running total of megabytes consumed, highlighting bandwidth savings.

### 2.4 Interactive Scenario Playground & Control Center
- **Scenario Configuration Controls**:
  - Dropdown selector for video clips and network trace profiles.
  - **Custom Network Trace Drawer**: Interactive canvas allowing users to draw a custom bandwidth profile curve to stress-test the ABR algorithms in real time.
- **Algorithm Hyperparameter Sliders**:
  - Sliders for $w_m$ (Motion Weight) and $w_c$ (Complexity Weight).
  - Toggle between Baseline ABR, Deterministic Perceptual ABR, and ML2's Learned Policy.
  - "Run Simulation" button with instant visual diff.

### 2.5 Comparative Research Scorecard & Reporting
- **Summary Metrics Table**:
  - Side-by-side comparison table summarizing:
    - **Average VMAF** (Primary Quality — Higher is better)
    - **Quality per MB (VMAF / MB)** (Primary Efficiency — Higher is better)
    - **Total Bandwidth Consumed (MB)** (Lower is better at equal quality)
    - **Rebuffering Stall Duration & Ratio (%)** (Lower is better)
    - **Startup Latency ($s$)** (Lower is better)
- **Radar / Spider Chart**:
  - Multi-dimensional QoE visualization comparing Quality, Stability, Buffer Safety, and Bandwidth Economy.
- **One-Click Export**:
  - Export full evaluation reports as structured JSON, CSV, or printable PDF summary.

## 4. Cross-Team Technical Interfaces & Contracts

### 4.1 Interface to DC (Rust Simulation Core)
- **CLI & Output Schema Ingestion**: WB consumes the JSON schema defined by DC (`SimulationReport`):
  ```json
  {
    "policy": "perceptual",
    "video": "mixed-complexity",
    "trace": "sudden-degradation",
    "chosen": [3, 3, 4, 2, 1, 1, 2, 3],
    "total_bytes": 11400000,
    "rebuffer_s": 0.0,
    "mean_quality": 84.6,
    "quality_per_mb": 7.4
  }
  ```
- WB formats and presents this data without altering metric definitions or calculation methods.

### 4.2 Interface to ML1 (Media Assets)
- WB loads the chunked `.mp4` media files and `.m3u8` manifests generated by ML1 into the web server's static asset directory (`web/public/media/`).
- The player loads chunks corresponding to the representation IDs selected by the simulation.

### 4.3 Interface to ML2 (AI Insights)
- Display ML2's predicted vs actual throughput curves and feature importance explanations in the dashboard's "AI Insights" panel.

## 7. Verification & Acceptance Criteria

1. **Player Synchronization**: Play, pause, seek, and stall events on the dual players must remain synchronized within a $\pm 100\text{ ms}$ threshold.
2. **Real-Time Responsiveness**: Simulation execution and graph rendering for a 60-second video trace must render within $< 2.0\text{ seconds}$ from clicking "Run Simulation".
3. **Cross-Browser Compatibility**: The dashboard must run without console errors or layout breakage on modern Chromium (Chrome/Edge), Firefox, and Safari.
4. **Accurate Telemetry Representation**: Graphs must accurately reflect the exact numerical values output by DC's Rust engine without interpolation distortions.
